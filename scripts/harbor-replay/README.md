# Harbor source replay

`go build ./cmd/aries-harbor` builds the native vHive runner. With only
`-trajectory` and `-rollout` it inspects an exact reviewed ATIF/native pair.
Its manifest pins both source byte hashes, the task, image digest, default
working directory, and reviewed effects. The native replay verifies the
requested image digest before creating a VM. The operator still needs the
task's original OCI image in the selected containerd namespace.

For the original Git recovery sessions, pass `-ripgrep` with the published
Codex 0.151.0 Linux x64 ripgrep executable. The starting Git object and reflog
checks run during guest setup.

For regex-log and constraints-scheduling, prepare the source tool layout with
Python 3.11+ and the exact Ubuntu Noble amd64 packages recorded under
`packages/`. Ubuntu mirrors or a local package archive must retain the listed
versions. From this directory run:

```sh
python3 prepare-codex-tools.py codex-harbor-tools.tar.gz package-cache
python3 prepare-os-tools.py regex-log regex-log-debs.tar.gz
python3 prepare-os-tools.py constraints-scheduling constraints-scheduling-debs.tar.gz
```

Pass `-codex-tools codex-harbor-tools.tar.gz` and the corresponding
`-os-tools <task>-debs.tar.gz`. The guest installs the checked Ubuntu packages
offline. Guest setup installs the public Node 22.23.2 / Codex 0.151.0 prefix
under its recorded NVM path. Reviewed calls reference the Codex native
executable solely for the recorded local patch operations. The recorded OS
tool version is unavailable. Package versions, initial task checks and setup
time are retained in the log. The synthetic schedule input checks bind all
three original calendar contents. Output includes the final task artifact
digest after the recorded session ends. The original agent's transient
plugins, temporary files and original wall clock can produce differences in
directory lists or dynamic calendar identifiers.

Use `-log` with a new path for each attempt. The `-observer` executable
accepts `phase runtime-id step socket` and blocks the next replay action until
capture ends. The `-sampler` and `-samples` pair starts the one-second host
sampler after restore. The log preserves actual exit status and distinguishes
missing mixed-stream order, source truncation and differing text.

The two foreground-only overfull-hbox recordings use the matching
`overfull-hbox-debs.tar.gz`, 2 vCPUs, 4096 MiB memory, and 10240 MiB disk.
Guest setup verifies each original TeX input hash. In trial 337f0b12, four
later commands refer to the directory name generated by a recorded mktemp
call. For that trial a hashed guest helper allocates the original unique
0700 directory when the original template is requested. The other trial
retains the original native mktemp behavior. Its subsequent commands read
their dynamic directory through a temporary file as recorded.

Code-from-image uses its original Python image and `-codex-tools` without
Ubuntu package additions. The live image operation reads the reviewed file
from the guest, validates and decodes its PNG, then serializes the same
high-detail image attachment recorded in the native session. Each of the five
source attachments contains the same 95,041 bytes as the task image. For the
one intercepted pure patch command, the source response has the native
patch envelope. Its original patch argument is dispatched through the
official fixed patch-only mode in the guest.

Two reviewed circuit-fibsqrt sessions yield while their real guest compile or
verification process is still running. ARIES streams both output channels
while inferred model time elapses, returns each chunk once, and binds later
empty write_stdin polls to that same live process. The initial yield starts
at host dispatch and includes guest transport setup. A live process running
at a yield is encoded as protocol status -1. Polls use the source harness's
five-second minimum, established by the repeated 5.00-second observations
at a requested 1000 ms. A process completing earlier or later than the
recorded state is retained as divergence.

Measured image runs require `-image-helper` built by
`scripts/harbor-image/build.sh` from the ARIES root with Rust 1.95.0 and the
musl target. The static helper uses Codex 0.151.0's pinned image crate and
returns the complete high-detail attachment after reading and decoding it
inside the guest. ARIES verifies the resulting wire bytes at the original
tool boundary. Earlier diagnostics on revision 1f2a2d1 read the PNG in the
guest and decoded it on the host. Their logs identify that revision.
