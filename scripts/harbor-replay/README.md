# Harbor source replay

`go build ./cmd/aries-harbor` builds the native vHive runner. With only
`-trajectory` and `-rollout` it inspects an exact reviewed ATIF/native pair.
Its manifest pins both source byte hashes, the task, image digest, default
working directory, and reviewed effects. The native replay verifies the
requested image digest before creating a VM. The operator still needs the
task's original OCI image in the selected containerd namespace.

For the original Git recovery sessions, pass `-ripgrep` with the published
Codex 0.151.0 Linux x64 ripgrep executable. The starting Git object and reflog
checks run during guest setup.

For regex-log and constraints-scheduling, prepare the source tool layout with
Python 3.11+ and the exact Ubuntu Noble amd64 packages recorded under
`packages/`. Ubuntu mirrors or a local package archive must retain the listed
versions. From this directory run:

```sh
python3 prepare-codex-tools.py codex-harbor-tools.tar.gz package-cache
python3 prepare-os-tools.py regex-log regex-log-debs.tar.gz
python3 prepare-os-tools.py constraints-scheduling constraints-scheduling-debs.tar.gz
```

Pass `-codex-tools codex-harbor-tools.tar.gz` and the corresponding
`-os-tools <task>-debs.tar.gz`. The guest installs the checked Ubuntu packages
offline. Guest setup installs the public Node 22.23.2 / Codex 0.151.0 prefix
under its recorded NVM path. Reviewed calls reference the Codex native
executable solely for the recorded local patch operations. The recorded OS
tool version is unavailable. Package versions, initial task checks and setup
time are retained in the log. The synthetic schedule input checks bind all
three original calendar contents. Output includes the final task artifact
digest after the recorded session ends. The original agent's transient
plugins, temporary files and original wall clock can produce differences in
directory lists or dynamic calendar identifiers.

Use `-log` with a new path for each attempt. The `-observer` executable
accepts `phase runtime-id step socket` and blocks the next replay action until
capture ends. The `-sampler` and `-samples` pair starts the one-second host
sampler after restore. The log preserves actual exit status and distinguishes
missing mixed-stream order, source truncation and differing text.

The two foreground-only overfull-hbox recordings use the matching
`overfull-hbox-debs.tar.gz`, 2 vCPUs, 4096 MiB memory, and 10240 MiB disk.
Guest setup verifies each original TeX input hash. In trial 337f0b12, four
later commands refer to the directory name generated by a recorded mktemp
call. For that trial a hashed guest helper allocates the original unique
0700 directory when the original template is requested. The other trial
retains the original native mktemp behavior. Its subsequent commands read
their dynamic directory through a temporary file as recorded.

Code-from-image uses its original Python image and `-codex-tools` without
Ubuntu package additions. The live image operation reads the reviewed file
from the guest, validates and decodes its PNG, then serializes the same
high-detail image attachment recorded in the native session. Each of the five
source attachments contains the same 95,041 bytes as the task image. For the
one intercepted pure patch command, the source response has the native
patch envelope. Its original patch argument is dispatched through the
official fixed patch-only mode in the guest.

Two reviewed circuit-fibsqrt sessions yield while their real guest compile or
verification process is still running. ARIES streams both output channels
while inferred model time elapses, returns each chunk once, and binds later
empty write_stdin polls to that same live process. The initial yield starts
at host dispatch and includes guest transport setup. A live process running
at a yield is encoded as protocol status -1. Polls use the source harness's
five-second minimum, established by the repeated 5.00-second observations
at a requested 1000 ms. A process completing earlier or later than the
recorded state is retained as divergence.

Measured image runs require `-image-helper` built by
`scripts/harbor-image/build.sh` from the ARIES root with Rust 1.95.0 and the
musl target. The static helper uses Codex 0.151.0's pinned image crate and
returns the complete high-detail attachment after reading and decoding it
inside the guest. ARIES verifies the resulting wire bytes at the original
tool boundary. Earlier diagnostics on revision 1f2a2d1 read the PNG in the
guest and decoded it on the host. Their logs identify that revision.

The reviewed video-processing occurrence installs toml inside its original
guest. Supply an isolated v1 daemon and the CNI network, configuration,
binary and cache directory flags. Guest DNS, route and HTTPS reachability
are verified around restore, and the final pip report records the resolved
distribution URL and checksum. The amd183 validation profile uses a dedicated
bridge, private CNI state, PyPI TLS endpoints and the site's resolver. Its
scoped firewall rule can be removed with
`provision-pypi-cni.sh PRIVATE_CNI_DIRECTORY remove`. The CNI binary versions
are containernetworking/plugins v1.9.1 and awslabs/tc-redirect-tap
34bf829e9a5c as pinned by firecracker-containerd.

To package strict video recordings, run
`prepare-image-circuit-cohort.py --video CACHE RECEIPTS NEW_BUNDLE`.
The bundle retains the signed source pair, validated runner, guest image
codec, and public package provenance for each eligible recording. Copy its
`cni/` directory to a private writable location on the worker. Run
`provision-pypi-cni.sh PRIVATE_CNI install video-amdNNN`, then
`run-reviewed-cohort.py RUNTIME UNIT BUNDLE VARIANT BUNDLE/manifest.json --video-cni PRIVATE_CNI`.
The verifier compares the restored guest's image bytes with each original
attachment, verifies the input video and final TOML, and checks the wheel
hashes and package service reachability across restore.

Selected video, circuit and token-count recordings need the Debian
Bookworm GNU patch package. Build the verified archive with
`prepare-os-tools.py bookworm-patch circuit-patch-debs.tar.gz` using
Bookworm APT indices, or add `--package-dir RETAINED_DEBS` to use locally
archived package bytes. The same option reconstructs the token-count curl
archive with `dataset-bookworm-curl`.

The SPARQL runner preserves recorded native web-search completion events
and their source gaps as host boundaries. Their start timestamps and results
are absent from the original recordings. Guest pip and direct PyPI requests
use the original commands and a dedicated network. The prepared guest checks
the source graph and query hashes, keeps RDFLib absent at session start, and
checks the live package report against the reviewed version and wheel hashes.

Build the offline OS tool archive with
`prepare-os-tools.py sparql-university CACHE/sparql/sparql-university-packages.tar.gz`.
`prepare-sparql-cohort.py CACHE RECEIPTS NEW_BUNDLE` packages successful live
fidelity trials with their exact source pairs, adapters, packages, tracer and
CNI binaries. The cache needs the private logs under `sparql/` and the original
source pairs under `sources/sparql-university/`. Keep the bundle private when
copying it to a worker. Unvalidated trials remain in `pending.json`.

On the selected study worker, verify the bundle's `SHA256SUMS`, load the
reviewed OCI digest into the runtime namespace and run
`provision-sparql-cni.sh BUNDLE/cni install amdNNN` with that worker's physical
label. Run `run-reviewed-cohort.py` with `BUNDLE/manifest.json` and
`--sparql-cni BUNDLE/cni`. The runner checks stage integrity and verifies
the replay's guest statuses, external boundaries, HTTPS probes, final query,
and dependency bytes. The CNI traffic scope is the site's DNS resolver and
TLS service endpoints for PyPI, the public bootstrap and the raw GitHub
helper. Remove that scope with
`provision-sparql-cni.sh BUNDLE/cni remove amdNNN` when finished.

For the reviewed CPU Torch trial, use
`prepare-sparql-cohort.py CACHE RECEIPTS NEW_BUNDLE --task torch-tensor-parallelism`.
The cache needs the exact Torch adapter and private live log under `torch/`,
the source pair under `sources/torch-tensor-parallelism/`, and the pinned
common Ubuntu archive under `sparql/`. In the bundle, provision
`provision-sparql-cni.sh BUNDLE/cni install amdNNN torch` and select
`--torch-cni BUNDLE/cni` in the cohort driver. The adapter enforces the
source's 8 GiB guest envelope, completion boundary, ten live package
digests and exact output file. The bundle also lists the other four source
trials pending native fidelity. The CPU index and wheel download hosts use
a separate CNI scope from the SPARQL profile.

## Token counting and compiler builds

The token-count replay checks the original Hugging Face dataset and tokenizer
revisions before checkpoint and after restore. Its guest runs the original
package installs and tokenization commands. The final receipt preserves the
answer file digest, token total and downloaded wheel URLs and SHA-256 hashes.

Build a cohort from completed native validation receipts with
`prepare-image-circuit-cohort.py --dataset CACHE RECEIPTS BUNDLE`.
Its manifest identifies each source pair, validated binary and unavailable
external response. On the assigned worker, copy `BUNDLE/cni` to a dedicated
writable CNI directory, with dnsmasq available at `/usr/sbin/dnsmasq`. Run
`provision-pypi-cni.sh CNI_DIR install dataset-amdNNN` from revision 186bad7
or later. Then run
`run-reviewed-cohort.py RUNTIME UNIT BUNDLE VARIANT BUNDLE/manifest.json --dataset-cni CNI_DIR`.
The bridge provides private DNS and TLS access for four public dependency
hosts. The before/after probes record the guest's resolved addresses and the
two immutable Hub revision identifiers.

Four CompCert sources install Coq, Dune and Menhir through OPAM. Their
release manifest records the upstream archive URL, the official OPAM cache
URL, the archive checksum and the metadata bytes inspected for each source
release. The live guest reads OPAM metadata, executes the original install
and build, and records its resolved switch and cache hashes. The direct Coq
source trial uses its original Git clone instead. The current Ubuntu mirror
and OPAM index can have newer metadata than the recorded session.

For an uninstrumented timing investigation, `-diagnostic-process-drift`
retains an early real exit for later empty source polls. If a source
terminal poll finds a still-running process, the original reply records
that disagreement. The runner separately joins the process and records the
actual terminal status and remaining stream bytes. The primary cohort
verifier rejects these diagnostic receipts.
