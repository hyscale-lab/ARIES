# Repository sanitization replay

The original `run.sh` mounts the exact reviewed fixture and uses native reply checks. `build-retry.sh ARIES OUTPUT GO` builds the pinned retry overlay, and `stage-retry.sh ARIES SOURCES BINARY TRACER OUTPUT` binds five native source pairs and seals the worker files.

The retry adapter records each actual first reply. At a source-terminal boundary that returns a running process, it records an independent live continuation and that process's actual exit and output digests. The recorded and observed statuses remain visible. The application checks compare the three modified files to clean references from the pinned benchmark and inspect tracked changes against its specified Git commit. Private raw archives are retained for source auditing. Published receipts contain counts, timings, sizes, and digests.

`retry-controller.sh RETRY_STAGE ORIGINAL_STAGE` runs the assigned cells in order after its prerequisites and whole-worker idle have been established. It retains a completed original when its source, replies, final state, and trace files agree. The runner exports each closed retry archive before acknowledging the next cell.

[Benchmark reference](https://github.com/harbor-framework/terminal-bench-2-1/tree/12b7565679ce5006230b820666353673a133db93/tasks/sanitize-git-repo/tests)

If the strict image viewer rejects a different PNG size, the retry leaves its actual first reply intact. A separately timestamped guest read keeps the exact available PNG in the private archive and records its dimensions, size, and digest. This extra read runs within the observed tool interval.

A final-state digest can verify the required clean reference only when it matches the independent pinned-image reconstruction. When available, supply that reconstruction as the sixth argument to `stage-retry.sh`. The resulting sealed manifest controls whether a completed original satisfies the skip gate.
