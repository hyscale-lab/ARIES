Primary method: one footprint per LLM reasoning step

The window begins with the LLM's complete tool-request message and ends when all expected native results are ready to return to the LLM. The native synchronous before_message_write hook declares the full ordered, normalized tool-call ID/name list through /batch. The observer arms before acknowledging this declaration, before native harness preparation and execution. Assistant text, reasoning, arguments and result bodies are not duplicated in this metadata protocol.

Native scheduling is unchanged. Native admissions annotate the batch without reading or resetting the bitmap. Sequential gaps, parallel calls and all sandbox operations expanding those calls remain in the same armed window. Immediate validation/missing-tool results can have no admission hook. Every expected result still participates in completion. The last expected synchronous persistence hook collects once before acknowledging collected; earlier results acknowledge pending, even if no native call is active.

One matrix row is one LLM step. groups.jsonl holds one batch_begin declaration and one group_end reading per completed batch. Native call identities and hook times remain in steps.jsonl. The hierarchy is Session → user/harness Turn → LLM Step → native calls → bridge operations. Requested and completed IDs reconcile the observation with one native assistant response; the last acknowledgement must precede the next model dispatch. Per-call page sets were not measured.

Coverage is partial. The reading is VM-wide temporal evidence, including guest-kernel, background and host/VMM activity affecting guest RAM. Host-side harness RAM and filesystem cache outside guest RAM are excluded. Native result delivery can lag execution completion. Finite scans, endpoint checks and KVM translation limitations remain; measurement_valid certifies batch registration and expected-result completion, while coverage_complete:false rejects a complete causal trace claim. There are no interior bitmap resets within a primary LLM step.

The primary counting assumption remains observed GPAs union recorded unknown GPAs; raw classifications and endpoint nonresident ranges remain separate. Historical single-call, busy-period and experimental segmented schemas retain their original granularity and are never silently relabeled as LLM reasoning steps.

Kernel bitmap I/O limit: the current collector bounds each idle-bitmap read/write to 4096 bytes (512 64-bit words), matching the Linux 6.8 binary-sysfs limit. Larger /proc metadata batches remain unchanged. Exact-length checks reject genuine short I/O. The older oversized batching can explain missing later windows in retained failed attempts; completed full-write/full-read windows are not retroactively invalidated. Source: Linux kernfs read/write implementation. A zero-mask/non-System-RAM-hole kernel probe confirmed clipping without affecting active guest PFNs.

Historical single-window pilot and shared idle-page mechanism

The footprint is the set of guest RAM pages observed during one complete LLM-issued tool-call step. The sandbox remains the same VM across steps; all harness operations implementing a tool call share one observation window.

  1. Before the step: enumerate resident pages backing the sandbox VM's guest RAM, check which pages support idle tracking, and mark eligible pages idle. Unsupported pages are retained separately.
  2. Execute the whole step: release the native harness to run every sandbox operation belonging to that LLM tool call. The collector does not reset between those operations.
  3. When the tool result is ready: read the idle bitmap. Eligible, stably mapped pages whose idle bits cleared are the observed touched set. Save their guest page addresses and the separate unknown-page addresses/reasons before acknowledging result persistence to the harness.
  4. Start a fresh observation for the next step: re-arm the bitmap before the next tool call. This clears access-tracking history while preserving the sandbox's memory and filesystem changes. LLM inference lies outside the bracketed tool interval; arm/collection scan times are recorded separately.
  5. Calculate footprint and overlap: form one unique page-address set per step, count its pages, and multiply by 4096 bytes. Compare two sets using intersection divided by union (Jaccard).
Observed_i = eligible pages whose idle bits cleared during step i's observation
Unknown_i  = recorded pages whose access state could not be classified
Counted_i  = Observed_i ∪ Unknown_i                 [requested counting assumption]
Footprint_i = |Counted_i| × 4096 bytes
Jaccard(i,j) = |Counted_i ∩ Counted_j| / |Counted_i ∪ Counted_j|

Scope: this is guest RAM accessed during the step's observation window. It includes guest-kernel, background-process and host/VMM activity affecting those pages; it does not isolate the foreground command's allocations. Host-side filesystem cache outside guest RAM is not included. Read and write touches are combined. The finite arm/collection scans and unknown-page inclusion mean this is an operational footprint estimate, not an exact complete causal trace. Pages nonresident at every inspected endpoint are not automatically counted.

Technical details: how page identities and idle bits were obtained

The idle collector reads host PFNs backing Firecracker guest RAM. The matrices compare guest physical page addresses (GPAs), not host PFN numbers. No tool-process virtual-address walk or guest-process pagemap read was used for the paid run.

  1. Capture the actual RAM mappings. Before VM creation, the worker attaches strace -f -e trace=ioctl to firecracker-containerd. The parser retains only successful KVM_SET_USER_MEMORY_REGION records: slot, guest physical base, host userspace base and size. It resolves the tracing thread to its VMM PID through /proc/<tid>/status, matches the expected VM ID in the process command line, and requires exactly one matching VMM. Tracing is detached before the first measured step. The historical paid fix-git pilot used 4 GiB of RAM with slots at [0, 3 GiB) and [4 GiB, 5 GiB); the 3–4 GiB hole is not RAM. Suite tasks use their own captured native 2, 4 or 8 GiB layouts.
  2. Translate each guest page to a host virtual address. For a 4096-byte-aligned GPA within a captured slot: 
    HVA = slot.userspace_addr + (GPA - slot.guest_phys_addr)
pagemap_byte_offset = (HVA / 4096) * 8
    The collector runs with host-root privileges on the worker and reads 64-bit entries from /proc/<Firecracker PID>/pagemap. It checks present bit 63, then extracts host_PFN = entry & ((1 << 55) - 1). PFN visibility requires host CAP_SYS_ADMIN; zero/masked PFNs cannot be used. Entries without the present bit are retained as nonresident address ranges, not decoded as physical frames. Pagemap reads are batched in at most 8192-entry chunks.
  3. Check whether the PFN supports this measurement. The collector reads the 64-bit entries at PFN * 8 in /proc/kpageflags and /proc/kpagecount. Eligible frames must be resident, on an LRU list, noncompound base pages, neither KSM nor zero pages, and have mapping count exactly one. Unsupported frames receive an explicit unknown reason. Sparse contiguous metadata accesses are batched rather than scanning physical-address holes.
  4. Arm once per selected observation window. In the primary suite, the synchronous before_message_write hook declares the complete LLM tool request and arms the observer. The historical single-call pilot used the awaited before_tool_call hook instead. For each eligible host PFN it writes a 1 to its idle bit: 
    bitmap_byte_offset = (PFN // 64) * 8
bit_mask = 1 << (PFN % 64)
    The interface is /sys/kernel/mm/page_idle/bitmap. One window covers every constituent sandbox operation of that LLM-issued tool call. The observer is re-armed before the next step, preserving guest RAM and disk contents. It does not sample at a fixed periodic cadence.
  5. Collect before returning the result to the LLM. The synchronous, nonsynthetic tool_result_persist hook waits for the observer's completion acknowledgement. Collection rereads residency/PFN mappings, reads the armed idle words, then rereads mappings once more. Only pages whose host PFN and eligibility stay consistent across these endpoint checks are classified: a cleared bit is recorded as touched; a still-set bit is recorded as idle. This detects read-or-write together, not separate read and write sets. PID start-time checks guard against observing a replaced VMM.
  6. Save identities and calculate overlap. Host PFNs are temporary collector state; the run did not retain full per-step host-PFN tables. Raw records retain accessed_gpas, idle_gpas, unknown_gpas with reasons, nonresident ranges, VM/PID identity and arm/scan timestamps. GPA entries are byte addresses; dividing by 4096 gives the guest frame number. Comparisons are within the same guest lifetime. A GPA can be reused for another guest allocation, so overlap does not prove identical data or object ownership.

Current counting policy: at the user's request, each primary comparison set is accessed_gpas ∪ keys(unknown_gpas). Jaccard is intersection size divided by union size. All unknown categories are included under this explicit assumption; raw classifications and the original observed-only matrix remain intact. Nonresident-at-both-endpoints ranges are not automatically added.

Measurement limits: the VMM continues running while arm/collection scans proceed. The window is not an atomic snapshot; newly resident pages are unarmed, and transient changes between endpoint checks may be missed. Kernel, background and host/VMM accesses can contribute. Unchanged idle bits can miss accesses through KVM translations. Therefore neither the observed-only nor the unknown-inclusive matrix certifies a complete, exclusively tool-caused access set. No RAM contents are read by this metadata collector.

How the UFFD pilot differs

The separate snapshot pilot does not obtain PFNs from pagemap. Firecracker passes a userfaultfd descriptor and memory-region metadata to the handler. For each missing-page fault, it aligns the host fault address to 4096 bytes, finds its region and computes snapshot_offset = region.offset + (aligned_fault_address - region.base_host_virt_addr). The handler supplies that single page from the memory snapshot using UFFDIO_COPY and logs its snapshot offset, first-fault flags and phase. Those offsets—not host PFNs—identify pages across restores of the same VM layout. The native handshake does not provide GPAs; no GPA mapping was assumed for this pilot. Unlike the idle metadata collector, the handler reads backing snapshot contents to restore pages, but does not write page contents into the fault log.

Restore, identity validation, tool execution and snapshot writing are separate phases. A page supplied during restore does not fault again on subsequent tool accesses. Tool-only first faults and the restore-through-tool envelope are consequently reported separately, while snapshot-writing faults are excluded from both. This deterministic UFFD pilot is distinct from the paid, idle-tracked LLM session.
