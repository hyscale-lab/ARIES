ARIES is deployed in namespace {{ .Release.Namespace }}.
{{- if .Values.bridge.enabled }}

The tool bridge runs as {{ include "aries.bridge.fullname" . }}. Check it is ready with

  kubectl -n {{ .Release.Namespace }} get pods -l app.kubernetes.io/name=aries-bridge

Profiles use it with "bridge": {"deployment": "kubernetes"}.
{{- end }}

The runner is not in the cluster. Set up its host from your machine with

  go run ./k8s/setup/aries-setup setup_runner

then, on that host,

  cd ~/aries && ./bin/aries profiles/hermes-tb2-fix-git-deepseek-k8s-pods.json
{{- if .Values.openclaw.enabled }}

The OpenClaw gateway is deployed. Reach it with

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "aries.openclaw.fullname" . }} {{ .Values.openclaw.service.port }}:{{ .Values.openclaw.service.port }}

and point the harness gateway URL at ws://127.0.0.1:{{ .Values.openclaw.service.port }}.
The pod waits for ARIES to stage its runtime before the gateway starts, so it
reports NotReady until then — that is expected.
{{- end }}
